PART A QUESTIONS

1. Why does p + 1 add 4 bytes for an int *? What about a char *?
   Pointer math moves by the size of the type. An int is usually 4 bytes,
   so p + 1 moves 4 bytes. A char is 1 byte, so a char * moves 1 byte.

2. What does end - start mean for two pointers in the same int array?
   It tells me how many elements are between the pointers, not how many
   bytes. For example, &prices[4] - &prices[0] is 4.

3. Why is *(prices + 5) undefined behavior for an array of length 5?
   The valid indexes are 0 through 4. prices + 5 is past the end of the
   array. The pointer value itself is okay to use as a loop limit for
   comparing, but reading from it is not safe even if it compiles.

PART B QUESTIONS

1. How does drink_length know when to stop?
   A C string ends with '\0'. The pointer moves one character at a time
   until it reaches '\0'. Then p - name gives the length.

2. When is prices[i] clearer, and when is p++ better?
   prices[i] is clearer when I need a specific index. A p++ walk is useful
   when I want to go through every item in order.
